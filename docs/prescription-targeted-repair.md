# Targeted repair operations

Repair is disabled by default (`PRESCRIPTION_REPAIR_ENABLED=false`). Configure an explicit Gemini model/key and positive `PRESCRIPTION_REPAIR_TOKEN_UNITS`, `PRESCRIPTION_REPAIR_SECONDS`, and `PRESCRIPTION_PROVIDER_MAX_OUTPUT_TOKENS` before enabling. `PRESCRIPTION_REPAIR_MAX_ATTEMPTS` defaults to one. Units conservatively count complete UTF-8 prompt/input bytes plus the output cap; they are not billed token usage. Shared provider admission remains separately enforced.

The internal `repair_prescription_section` Celery task takes a saved review ID, a supported clinical collection and stable record ID, affected field names, and one to four verified page snippets. `prepare_saved_repair` builds the request from the authoritative saved draft and associated document pages. Only unresolved supported fields are eligible; patient identity and boolean interpretations are excluded. The exact assembled outbound input needs its own non-sensitive hash approval under the provider data policy. Approval of a different full extraction input does not approve repair.

LangGraph dispatches a single bounded provider node and a proposal validation/storage node. Function calling is disabled. The proposal must contain allowlisted literal evidence-backed values and match the saved revision/document and protected field values. Request/proposal artifacts are append-only private binary checkpoint rows; the original extraction and review stay unchanged. Operational checkpoint cleanup retains these repair artifacts.

Recover with the same document workflow/request identity and a current lease. A successful audited answer resumes storage without dispatching again. A running/failed ambiguous invocation never automatically redispatches: preserve the usable exception draft and investigate. This does not promise exactly-once external API execution. A second workflow cannot reset a document's repair accounting. Late responses, stale revisions, changed models/data-policy partitions and approved/published reviews are rejected. Celery expected budget/policy/validation exceptions return `exception_draft`, release the lease and do not recursively retry.

Repair dispatch remains an internal opt-in execution path. Saved valid proposals are exposed only through the authorized document repair-proposals endpoint and shown on the actual correction form. Explicit adoption changes the local form only; dirty/locked/stale reviews and reviewer-edited records cannot adopt. The normal saved-revision review API persists adopted fields while retaining original extracted evidence. Invalid/stale artifacts are omitted; no prompt or full repair request is exposed. Graph extraction-wide provider budgets are implemented separately. No automatic clinical publication, patient association or production rollout is enabled by adding this task.
